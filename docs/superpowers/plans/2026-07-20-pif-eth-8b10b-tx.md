# pif_eth — 8b/10b line-coded Ethernet TX (implementation plan / as-built)

Date: 2026-07-20 — Status: complete

See the design: `../specs/2026-07-20-pif-eth-8b10b-tx-design.md`.

## Steps

1. **Python reference layer** (`source/pif_eth/`) — done
   * `codec.py`: 8b/10b encode/decode with running disparity; K28.5 comma;
     `build_dram0_lut()`; `build_decode_map()`.
   * `crc32.py`, `prng.py`: Ethernet FCS and xorshift32 references.
   * `frames.py`: BERT (132 B) and UDP (`Hello World Text`, 64 B) builders.
   * `decoder.py`: bit/symbol stream → frames (comma-delimited).
   * `pcap.py`: classic-format pcap writer (Ethernet link type).
   * Locked by pure-Python tests: round-trip over all 256 octets in both RD
     contexts, RD bounded ±1, no run > 5, CRC check value, frame shapes.

2. **PRU0 firmware** (`source/pif_eth/pif_eth_tx.asm`) — done
   * Self-configures GPCFG0 (perif mux), TXCFG (25 MHz bit clock), CH0CFG0
     (continuous mode); selects ch0 via a byte-2 R30 write (a byte-0 write
     would push a stray FIFO byte).
   * Subroutines: `prng_fill`, `crc32_compute`, `send_frame`, `emit_comma`,
     `push_symbol`, `push_byte`, `flush_pad`, `drain_wait`, with fixed
     return-address registers per nesting level (no call stack).
   * Per-frame go-flag handshake so the host can capture each burst.

3. **Driver + integration** (`source/pif_eth/driver.py`) — done
   * Loads LUT + control block into DRAM0, runs the firmware one frame at a
     time, reconstructs each burst's serial line from the perif channel's
     recorded transitions, decodes, checks BER, writes pcap.
   * `python3 source/pif_eth/driver.py 100` → 100 frames/type, BER 0, traces.

4. **Tests** (`tests/test_pif_eth.py`) — done
   * 18 tests incl. an MCP-server-driven run; full suite green (1159 passed).

## Notable gotchas resolved

* `and` immediates are 8-bit — the 10-bit `0x3FF` mask lives in a register.
* `ldi r30, 0` strobes byte 0 → pushes a 0x00 FIFO byte, corrupting the first
  burst; use `ldi r30.b2, 0` to select ch0 without a push.
* Continuous-mode FIFO under-runs if generation (PRNG/CRC) happens mid-stream,
  so each frame is a separate burst generated before its `tx_go`.
* The perif TX timeline only advances while PRU0 steps, so the firmware ends in
  a spin (not `halt`) and `drain_wait` keeps stepping until the burst fully
  serialises before the frame counter is published.
