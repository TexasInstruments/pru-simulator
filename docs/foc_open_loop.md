# FOC Open-Loop PWM Example

`source/foc_open_loop.asm` is ordinary PRU0 assembly that produces a three-phase
space-vector PWM pattern on `R30.0`–`R30.2`. It polls the simulator's IEP counter
and starts each period every 12,500 IEP ticks. With the shipped 200 MHz IEP
clock, that is 62.5 μs, or 16 kHz. The firmware requires matching 12,500-tick
control and PWM periods.

The output compare values follow TI's `SVGEN_runCom` phase order and common-mode
injection: A is α, B is −α/2 + √3/2 β, C is −α/2 − √3/2 β, then the midpoint of
the largest and smallest phase is removed. Centered phases saturate at
√3/4 Q15, which preserves the full linear β-axis vector while leaving the
low-time margin required for the following control update. The output is still
generated by normal PRU instructions and counted cycles; there is no simulator
callback that skips or replaces firmware execution. The phase order and
common-mode convention match TI's
[`SVGEN_runCom`](https://software-dl.ti.com/processor-industrial-sw/esd/motor_control_sdk/am243x/2025_00_00_06/docs/api_guide_am243x/svgen_8h_source.html).

At the shipped 250 MHz PRU0 and 200 MHz IEP clocks, the worst of the six
sector-vector updates measured 205 PRU cycles including 9 stall cycles. A
saturated vector leaves 838 IEP ticks, or 1,047 PRU cycles, before the next
period; the update therefore uses less than half of that interval. End-to-end
VCD checks keep the period within 50 ns of 62.5 μs for all six sectors and the
saturation case.

## Control ABI

The schema `schema/foc_control_abi.json` generates the Python packer and
assembly constants. Check or regenerate them with:

```bash
python -m tools.gen_foc_abi --check
python -m tools.gen_foc_abi
```

The little-endian configuration block is at `0x00010100`:

| Field | Type | Default | Meaning |
|---|---:|---:|---|
| `abi_version` | u32 | 1 | Firmware/config compatibility |
| `control_period_ticks` | u32 | 12,500 | Control update interval |
| `pwm_period_ticks` | u32 | 12,500 | PWM period |
| `phase_increment_q32` | u32 | 0 | Nonzero selects the six-sector rotating vector |
| `modulation_q15` | u32 | 16,384 | Magnitude used by the rotating vector |
| `alpha_q15` | s32 | 16,384 | Direct α input when phase increment is zero |
| `beta_q15` | s32 | 0 | Direct β input when phase increment is zero |
| `initial_phase_q32` | u32 | 0 | Starting angle for the rotating vector |

Alpha and beta use signed Q15, with accepted values from −32,768 to 32,767.
The firmware uses the direct α/β fields when `phase_increment_q32` is zero. A
nonzero increment advances the Q32 phase at each control update and selects
one of six 60-degree vectors scaled by `modulation_q15`.

## Pin-coupled motor and current model

The optional `foc_motor` `DeviceModel` observes the real PRU0 GPO0–2 PWM bus,
integrates a three-phase RL load using the configured PRU clock, and drives
phase-A and phase-B current measurements as push-pull PDM on GPI3 and GPI4.
Each output's PDM quantizer advances at its explicit sample clock, which
defaults to 20 MHz and holds its GPIO level between samples. This matches the
default SD channel clock; changing a PRU0 SD channel clock through the
simulator also updates the matching FOC output clock. It has no shared-memory
feedback path. Its profile is restricted to PRU0 and
sets that core's GPO drive mask to `0x7`, leaving GPI3/GPI4 owned by the model.
Because the profile controls the core's output mask, it cannot be attached
alongside another device on PRU0.
The usual internal sigma-delta pattern generators remain the default; an SD
channel can instead sample a physical GPI pin.

## Run with the MCP wrapper

```python
from pathlib import Path

from mcp_server.server import PRUSimulatorMCP
from pru_io import foc_control_abi as foc_abi

mcp = PRUSimulatorMCP("memory.cfg")
mcp.pru_device_attach(profile="foc_motor")
mcp.pru_sd_route_input(channel=0, pin=3)
mcp.pru_sd_route_input(channel=1, pin=4)
mcp.sim.memory.write(
    foc_abi.CONTROL_ADDRESS,
    foc_abi.pack_config(alpha_q15=0, beta_q15=16384),
)
source = Path("source/foc_open_loop.asm").read_text(encoding="utf-8")
mcp.pru_load(source, include_paths=["source"])
mcp.pru_vcd_export("/tmp/foc.vcd", max_steps=35000,
                   pins="0-4", include_gpi=True)
print(mcp.pru_device_state())
print(mcp.sim.sd_state("pru0")["input_routes"])
```

The VCD shows the actual PWM and current GPIO pins. Device state reports the
modeled phase currents and PWM period count; sigma-delta routes show which GPI
pins feed the selected channels. Disconnect the model with
`mcp.pru_device_detach("foc_motor")` to restore the previous GPO drive mask.
