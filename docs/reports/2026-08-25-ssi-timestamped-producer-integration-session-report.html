Date 2026-08-25 Target AM243x ICSSG, 300 MHz Tests passing

1 The Initial Request

The ARM application can form encoder positions every 960 ns while SSI requests are slower. This work adds a coherent timestamped ring, a shared IEP timebase, and a bounded PRU0 estimator that prepares the position for the next SSI frame without adding estimator work to the data-edge bit path.

Request, as summarized in the session record:

Publish timestamped ARM positions at approximately 960 ns, interpolate or extrapolate when the SSI clock restarts after tm, keep the PRU implementation fast and deterministic, support simulator and real AM243x hardware, validate through the Python MCP interface, and document the workflow. The final PWM producer remains external to this project.

3 Design Choices

Design decisions

3.1

256-entry ring with per-entry seqlocks

256 entries of 32 bytes in ICSSG shared RAM, with per-entry seqlocks.

3.2

Constant-time producer head

Constant-time producer head; PRU0 reads only two slots.

3.3

300 MHz IEP0, initialized by PRU1

300 MHz IEP0 initialized by PRU1 and read coherently through c26.

3.4

Estimator runs during idle time

Estimator runs during idle time; the request edge captures IEP and shifts.

3.5

Flexible timestamped binary/Gray packing

Timestamped binary/Gray packing supports explicit/right-aligned placement, zero padding, and 1..64-bit raw frames without changing the bit loop.

3.6

Integer encoder counts in UI/MCP trajectories

UI/MCP trajectories publish integer encoder counts while retaining continuous engineering motion.

3.7

Hold-last fallback with explicit status/counters

Hold-last fallback with explicit status/counters on invalid input.

3.8

Static prepacked frames remain the default

Static prepacked frames remain the default and retain 64-bit support.

Automated coverage includes IEP behavior, sample publication ordering, signed estimator arithmetic, paired PRU execution, rollover, generation changes, stale and overrun fallback, dashboard WebSocket actions, MCP operations, the new timestamped layout/Gray cases, and parent CCS source contracts. The focused SSI suite passed 148 tests, the parent suite passed 27 tests, and the UI/MCP subset passed 56 tests. Physical LaunchPad build and logic-analyzer acceptance remain the hardware verification step.

A live WebSocket/MCP-equivalent run of the 12-bit/4 MHz profile used a 288-tick producer period and a 250,000-count/s linear trajectory. PRU0 accepted coherent estimates with status zero and PRU1 published the dynamic value in the mailbox. The in-app visual browser was unavailable for this session, so the browser rendering itself remains a manual visual check.

6 Manual Simulator Flow

  1. Load the Generic SSI pair.
  2. Select Timestamped producer and Apply atomically.
  3. Configure a constant, linear, or triangle trajectory at 288 ticks.
  4. Start publication, run the pair, and inspect mailbox and producer diagnostics.
  5. Stop publication to verify stale hold-last behavior.
