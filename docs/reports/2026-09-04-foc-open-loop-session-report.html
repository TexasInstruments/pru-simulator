2 Overview: Consolidated Scope

Open-loop Field-Oriented Control (Level 1) on a single PRU core (pru0), with firmware, shared-memory ABI, Python motor model, and simulator UI tab. The project spans two concurrent work streams:

Plan A: Firmware + ABI (Session A)

A

PRU firmware pipeline (foc_open_loop.asm)

Config handshake → RC (ramp control) → RG (ramp generator) → sin/cos LUT → inverse Park → SVGEN (SVPWM). Q24 fixed-point, broadside MAC for multiplies, seqlock on PWM output. Built incrementally, test-driven, one macro at a time. Validated against pure-Python cross-checks for each stage.

A

Schema-driven ABI (foc_abi.json + generator)

Single source of truth for four shared-memory sections: control (host→PRU references), pwm_out (PRU→host duties), motor_fb (model→host feedback), sine_lut (host seed). Generator produces assembly, Python, and C snapshots, keeping offsets and layouts synchronized. Validated with 9 ABI tests.

Plan B: Simulator + UI (Session B)

B

Python motor model and runtime

IEP-clocked PMSM plant model (αβ electrical + mechanical integrator) reads duty cycles from pwm_out, simulates rotor dynamics, and writes currents + angle to motor_fb. Runtime wrapper manages lifecycle, reference staging, and LUT seeding. Enables co-simulation of firmware behavior.

B

MCP tool + WebSocket + UI tab

pru_foc_inject MCP tool (mirrors pru_uart_inject) loads firmware + model + runs in a single call. WebSocket emits real-time pwm_out and motor_fb snapshots. Motor Control UI tab includes reference form, rotary dial, and rolling plots for duty cycles, currents, and voltages. Responsive layout.

3 Design Choices

Firmware architecture (Plan A)

3.1

Q24 Fixed Point + Broadside MAC

Signed 1.7.24 (0x01000000 = 1.0) for all per-unit values matches TI DMC macro conventions. The PRU simulator's MAC (device 0) is unsigned only; Q24 operands decompose into (sign, |magnitude|) via branchless two's-complement, multiply magnitudes, then reapply sign. Avoids branching and label-scope collisions.

3.2

Ramp control with unsigned branch predicates

Simulator's QBGT/QBLT compare unsigned. To clamp speed_setpoint toward speed_ref by ±ramp_rate, extract the sign of the difference, compute unsigned magnitude, compare against ramp_rate, then reapply the sign — entirely branchless.

3.3

Sine LUT: 2048 entries, quarter-table cosine offset

32-bit phase accumulator with 2048 entries (2^11) gives a 21-bit shift index. Cosine is 90° away: quarter-table offset (512 entries = 2048/4) with modulo masking reproduces quarter-wave symmetry. Nearest-neighbor lookup (≈0.088° step) is acceptable for Phase 1; interpolation deferred.

3.4

Seqlock on pwm_out and motor_fb

Future asynchronous readers (model, UI) need consistent snapshots. Seqlock (odd while writing, even when stable) ensures neither reader catches a torn update. Readers check seq before and after; if both are even and match, the read is valid.

3.5

Arithmetic right-shift synthesis

Simulator's LSR is logical only, not arithmetic. SVGEN's −0.5·Vβ and Vcom=(max+min)/2 both need sign-extending right-shift by 1. Synthesized as LSR ORed with the operand's sign bit (preserves two's-complement semantics).

3.6

Signed MIN/MAX via two's-complement bit-flip

Simulator's MIN/MAX is unsigned. For SVGEN's signed Va/Vb/Vc, each is XORed with 0x80000000 (flips sign bit) before MIN/MAX, then XORed back. Transforms unsigned order comparison to signed order exactly.

Simulator + UI architecture (Plan B)

3.7

Schema-generated Q24 ABI

The control, PWM output, motor feedback, and sine LUT sections are defined once in schema/foc_abi.json. Generated assembly, Python, and C snapshots keep the 0x10000 shared window, offsets, sizes, and seqlock layouts aligned with firmware and model.

3.8

IEP-clocked PMSM plant

The model integrates electrical current in αβ coordinates and mechanical torque using reference motor constants. Observer callbacks follow IEP time, while bounded substeps keep manual catch-up deterministic and numerically stable.

3.9

Host-side staged commit and raw state snapshots

FocRuntime seeds the 2048-entry sine table and commits references by writing the block before bumping requested_generation. The WebSocket exposes named raw ABI fields plus the model snapshot so the UI remains inspectable against shared memory.

3.10

Separate Motor Control workspace

The tab does not compete with the simulator's panel pool or Protocol Tools. It adds a small reference form, a measured/commanded angle dial, and rolling duty, current, and αβ voltage canvases, with responsive layout and accessible tab/panel attributes.

3.11

Plan A remains untouched

No source/foc_open_loop firmware or firmware documentation was invented in this checkout. The load path accepts the future default firmware location and also supports an explicit source payload for backend tests and parallel integration.

Found and corrected during implementation and reconciliation

3.12

Phase-to-αβ transform direction (Plan B)

The first plant pass treated inverse_clarke as a phase-to-αβ helper, but the reference function returns three phase values from αβ inputs. The focused motor test caught the mismatch; the model now uses an explicit phase-to-αβ transform for sampled PWM voltages.

3.13

FOC_SPEED_SCALE overflow (today's reconciliation)

Session B's schema defined FOC_SPEED_SCALE = 2863312 (0x2BB0D0). In firmware's RG (ramp generator), `ldi TMP2, FOC_SPEED_SCALE` exceeded the 16-bit immediate range and the assembler rejected the file outright; changed to `ldi32` (32-bit load via split-immediate). Both plans now compile and integrate correctly.

7 Today's Reconciliation: Merging Plans A and B

Two independent work sessions built complementary halves of the same project on parallel branches. Today, an orchestrating session fast-forwarded Plan B into the main branch, resolved collisions, and verified the integration.

Fast-forward and collision discovery

Session B's commit (feat: add open-loop FOC simulator UI) was fast-forwarded into main. During integration audit, two ABI files were found to have identical offsets, struct sizes, and seqlock layouts — both sessions had independently designed the same shared-memory map. The discrepancies were superficial: docstrings and a field rename (Session A's `loop_counter` vs. Session B's same-meaning constant). The canonical version in the repo (Session B's schema) was retained; no functional conflict.

Test filename collision

Session A originally created its firmware cross-check tests at tests/test_foc_open_loop.py. When Session B's commit was fast-forwarded in, it added its own file at that exact path — testing co-simulation (firmware + motor model) instead. To resolve the collision, Session A's firmware test file was renamed to tests/test_foc_firmware.py; Session B's tests/test_foc_open_loop.py (co-simulation) was left untouched. Updated design spec references at lines 134 and 162 accordingly.

FOC_SPEED_SCALE overflow bug fix

Session B's schema defined the constant FOC_SPEED_SCALE = 2863312 (0x2BB0D0). In the firmware's RG (ramp generator) stage, the sequence was:

ldi TMP2, FOC_SPEED_SCALE ; intended: load freq scale into TMP2

The PRU assembler's ldi (load immediate) accepts only 16-bit values (0-65535). Session A's original schema used a scale of 954, which fit; Session B's canonical value of 2,863,312 does not. The assembler rejected the file outright (LDI operand ... out of range for 16-bit immediate), failing all 9 firmware tests at load time — not a silent corruption. Fixed by upgrading to ldi32 (split-immediate loader, breaks 32-bit constants into two 16-bit stages and ORs them into the target register). Verified: all 9 firmware tests pass after the fix.

Final test-suite state

After the FOC_SPEED_SCALE fix, the full test suite passed: 1471 tests, 2 expected failures (unrelated to this work). One pre-existing import gap (numpy/matplotlib not available in Python 3.14 environment) does not block FOC tests, which use pure math and manual assertions. No new failures were introduced by the merge.
