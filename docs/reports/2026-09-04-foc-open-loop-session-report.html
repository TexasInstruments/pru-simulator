3 Design Choices

The new path is intentionally open-loop: PRU0 owns the control-side shared blocks, while the Python plant reads PWM output and publishes model feedback for observation.

Decided up front from the FOC specification

3.1

Schema-generated Q24 ABI

The control, PWM output, motor feedback, and sine LUT sections are defined once in schema/foc_abi.json. Generated assembly, Python, and C snapshots keep the 0x10000 shared window, offsets, sizes, and seqlock layouts aligned with the future firmware.

3.2

IEP-clocked PMSM plant

The model integrates electrical current in αβ coordinates and mechanical torque using the reference motor constants. Observer callbacks follow IEP time, while bounded substeps keep manual catch-up deterministic and numerically stable.

3.3

Host-side staged commit and raw state snapshots

FocRuntime seeds the 2048-entry sine table and commits references by writing the block before bumping requested_generation. The WebSocket exposes named raw ABI fields plus the model snapshot so the UI remains inspectable against shared memory.

3.4

Separate Motor Control workspace

The tab does not compete with the simulator’s panel pool or Protocol Tools. It adds a small reference form, a measured/commanded angle dial, and rolling duty, current, and αβ voltage canvases, with responsive layout and accessible tab/panel attributes.

3.5

Plan A remains untouched

No source/foc_open_loop firmware or firmware documentation was invented in this checkout. The load path accepts the future default firmware location and also supports an explicit source payload for backend tests and parallel integration.

Found and corrected during implementation

3.6

Phase-to-αβ transform direction

The first plant pass treated inverse_clarke as a phase-to-αβ helper, but the reference function returns three phase values from αβ inputs. The focused motor test caught the mismatch; the model now uses an explicit phase-to-αβ transform for sampled PWM voltages.
