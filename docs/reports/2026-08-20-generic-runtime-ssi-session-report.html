1 Prompt

Starting point, from the SICK SSI interface datasheet already reviewed in this project's history:

"We want to implement a generic encoder interface for both reader and emulated encoder cores that starts with predefined values like the ones right now (12 bits, 4 MHz, tm) but can be modified at runtime — changing bits, frequencies and timings. [...] first only focus on simulator; when all simulator projects are done and verified we will focus on real hw code composer project adaptation."

Everything below is the simulator-scoped slice of that request. The real CCS/R5/hardware port is explicitly deferred, tracked separately, and not started in this repository.

3 Design Choices

Architecture

3.1

One shared-memory config block, generated from a single JSON schema

Both PRU programs and the Python runtime layer read the same field offsets. A generator (tools/gen_ssi_abi.py) emits the .inc and .py files from schema/ssi_config_abi.json, with a drift test that fails if either output diverges from the schema — the two sides of the ABI can never silently disagree.

3.2

Generation-counter handshake for atomic config switching

requested_generation/pru0_ack_generation/pru1_ack_generation let a host stage a full config change and have both PRU cores adopt it atomically at their next idle-frame boundary, instead of racing a change into the middle of an in-progress frame.

3.3

Python layer plays the role real R5 firmware will eventually play

ssi_runtime.py's SSIRuntime holds named profiles and validates/stages/applies config exactly the way the real hardware's R5 core is expected to — neither PRU program can tell the difference between this module and real firmware, which is the point.

A real bug found and fixed mid-effort

3.4

Loopback-mode idle-gap reconfiguration deadlock

PRU0's idle-wait for the next clock edge was a genuinely blocking instruction with no way to notice a config change while parked; PRU1's longer inter-frame pause meant it always checked later — so a config change landing in that window could permanently stall both cores. Found during Task 5, independently reproduced by a reviewer, fixed by turning PRU0's blocking wait into a bounded poll that also re-checks for a config change every 64 iterations. The negative control (reverting the fix) was independently reproduced twice — once by the implementer, once by the reviewer — before the fix was accepted.

Deliberately deferred, not fixed

3.5

Async/sync position-formation timing is accepted but has no effect

formation_mode/formation_pause_outer_iters exist in the ABI and are set per-profile, but neither PRU program reads them — a gap in the original task briefs, confirmed by direct code inspection, and left unimplemented per an explicit decision to defer rather than expand scope further.

3.6

No encode-side position-value validation yet

decode_position() exists (wire → natural value); nothing on the encode side rejects a natural value that doesn't fit the configured resolution before it's packed into a frame slot. Same deferral decision as above. A third, related gap (alignment is also unread) was found during the final audit and documented the same way.

Manual UI validation

The dashboard now provides a dedicated Generic SSI Runtime panel. Validate the paired workflow through the browser; the direct Python/MCP path remains documented below for lower-level checks:

Dashboard panel

  1. Start the dashboard: python ui/server.py, then open http://localhost:8080.
  2. Click Load PRU0 emulator + PRU1 reader in the Generic SSI Runtime panel.
  3. Leave ABC, AAA, BCA, 12A, CC2, choose Mailbox + trace, and click Apply atomically.
  4. Enable Signal Graph recording when waveforms are needed, click Run pair, then Refresh.
  5. Change profile, width, timing, sequence, or fault settings and repeat Apply. Oversized raw values are rejected.

Direct Python/MCP path

  1. Start the dashboard: python ui/server.py
  2. Load source/ssi_generic_emulator/ssi_generic_emulator.asm on PRU0
  3. Load source/ssi_generic_reader/ssi_generic_reader.asm on PRU1
  4. Wire GPIO: PRU1 GPO0 (clock out) → PRU0 GPI16 (clock in); PRU0 GPO0 (data out) → PRU1 GPI8 (data in) — same convention as the fixed firmware
  5. Alongside the dashboard, in Python: rt = SSIRuntime(sim), then rt.stage("AFS_AFM60_MULTITURN_30BIT") / rt.apply() to push a named profile into the same shared memory the UI is showing
  6. Inject a frame value into a slot via ssi_config_abi.pack_frame_slot(...), run, and watch the clock/data lanes in the dashboard
  7. Cross-check with rt.read_mailbox() / rt.read_trace() (or the equivalent MCP tools) that the decoded position matches what was injected
