## What it is

Single-core **PRU0** firmware that transmits Ethernet frames as an **8b/10b**
line-coded serial stream on **perif channel 0** (continuous mode), plus a Python
golden-reference/decoder layer, driver, and pcap output. Lives in
`source/pif_eth/`.

- True 8b/10b with running disparity via a 256-entry **DRAM0 LUT** read with
  `LBCO` (`c24`); firmware xorshift32 PRNG + bit-serial CRC-32 FCS; K28.5
  inter-frame commas; per-frame go-flag handshake at DRAM0 `0x0418`.
- Two frames: **BERT** (132 B = 128 PRNG + CRC, no preamble/header) and **UDP**
  (`"Hello World Text"`, 64 B, valid Ethernet).

## How to run

```bash
# full flow: 100 frames/type, BER=0, writes pcaps under source/pif_eth/traces/
python3 source/pif_eth/driver.py 100
tshark -r source/pif_eth/traces/pif_eth_udp.pcap

# tests (18, incl. an MCP-server-driven run)
python3 -m pytest tests/test_pif_eth.py -q

# interactive UI
python ui/server.py                          # http://localhost:8080
python3 source/pif_eth/seed_ui.py bert       # seed DRAM0 + arm one frame
# then click Run in the browser, then Stop (Run is a toggle; no step-budget field)
```

## Notes for future work

- Second stage: broadside CRC accelerator (currently firmware bit-serial).
- Possible extension: stripe across all 3 perif channels for aggregate rate.
- 125 Mbaud is the documented target; the model uses TXCFG div=7 (25 MHz) so the
  single core keeps the FIFO fed — does not affect the byte stream or BER.
