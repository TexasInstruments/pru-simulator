### 1. `dec_lut.h` — the 8b/10b decode table as a C header

`source/pif_eth/dec_lut.h`, generated by `source/pif_eth/gen_dec_lut.py`.
`codec.build_dram1_decode_lut()` stays the source of truth; the script only
reformats.

**Chosen layout: 512 `uint32_t`, two symbols packed per word** — bits
`[15:0]` = symbol `2n`, `[31:16]` = symbol `2n+1`. That is the *exact 2 KB
DRAM1 image*, so C firmware can

```c
memcpy((void *)PIF_ETH_DEC_LUT_ADDR, dec_lut, sizeof dec_lut);   /* 0x0000 */
```

and land it where `lbco &r23, c24, r24, 2` reads it. The alternative — 1024
words, one per codeword, directly indexable — was rejected because it is 4 KB
and does *not* match the byte image the firmware expects. Consequence: index
through `PIF_ETH_DEC_ENTRY(sym)`, which unpacks the u16 half. Field masks
(`_OCTET_MASK`, `_VALID`, `_NEUTRAL`, `_RD_POS`, `_COMMA`) ship in the header.

`gen_dec_lut.py --check` compares the committed header against a fresh render
and exits 1 if stale, without rewriting. Worth wiring into CI or a pre-commit
hook — nothing enforces it today, so a `codec.py` change can silently leave
the header behind. `main()` also round-trips every render back through
`parse()` before writing, so a formatting bug cannot emit a header that fails
to decode to the codec's bytes.

### 2. Burst instructions require `&` on the first operand

`LBBO/SBBO/LBCO/SBCO` take the *address* of the register file, so clpru wants
`lbco &r0, c24, 0, 4`. 98 sites across the perif and pif_eth firmware were
missing it.

**No semantic change** — `core/operands.py:83` already matched `^&?r(\d+)…`,
so both spellings parse to identical `Register` objects. `XIN`/`XOUT`/`XCHG`
(21 sites) were checked and already correct.

Trailing comments kept their column by absorbing one space from the gap
before `;` (only where the gap was ≥2).

### 3. Indent 4, not 8

Twelve firmware files used an 8-space indent against a 4-space house style
(`references/` and `tests/asm/` were already at 4). Also normalized the two
stragglers at 2 (`program.asm`) and 5 (`running_led.asm`) — they were never at
8, so this went slightly past a literal reading of the ask; revert if unwanted.

Dedented by **exactly 4** rather than reflowing to a fixed column. Every
non-empty line in those files sat at column 0 or ≥8, so a uniform shift
preserves all relative alignment — specifically the aligned comment
continuations in `pif_eth_rx_o1_raw.asm` and `pif_eth_crc32.inc` (36 → 32).
CRLF on `program.asm`/`running_led.asm` was preserved (5-line diff, not a
whole-file rewrite).

## The verification harness — reuse this

Both asm-wide changes were verified the same way, and the technique is the
reason they can be trusted at 98 and 1226 sites:

```python
# dump opcode+operands for every source/**/*.asm, ignoring source_text/line
Parser().parse_text(f.read_text(), include_paths=[str(f.parent),
                                                 str(f.parent / "include")])
```

Snapshot before, snapshot after, `diff`. Both changes produced **identical
parsed output for every file** — a much stronger claim than "tests pass",
because it covers files no test exercises. For the style commit,
`git diff -w` was additionally confirmed empty.

The two commits were deliberately split so the re-indent reviews with
`git diff -w`. Eight files were touched by *both* changes, so splitting meant
reverting `source/` and replaying each step from scripts; the reconstructed
tree was checked byte-identical (`diff -r`) against a backup of the combined
state before committing.

## Gotchas worth carrying

- **`memory.cfg` line endings, again.** The repo blob is CRLF; this PC writes
  LF, so the file shows as fully rewritten on every touch and blocked the
  `git pull --ff-only`. The local edit turned out to be content-identical to
  the incoming one (both `250`), so discarding it was free — but check with
  `diff <(tr -d '\r' …)` before assuming that. A `.gitattributes` entry
  (`memory.cfg -text` or `* text=auto`) would end this permanently; still not
  done.
- **`docs/` was left alone.** 44 old-syntax citations across plan/spec/handoff
  files, and 8-space listings throughout. They are dated records of the code
  as it was, so rewriting them would falsify the archive. Same call for the
  inline asm fixtures in `tests/test_dram_mapping.py` (7) and
  `tests/test_perif_server.py` (1) — those are also now the only remaining
  coverage that the parser accepts the bare, `&`-less form.
