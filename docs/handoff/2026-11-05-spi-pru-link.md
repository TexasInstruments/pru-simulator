## Gotchas before touching this
- The GPI hop delay is 5 cycles (Ruling R6), calibrated to the user's silicon scope measurement of 18 ns at 333 MHz (wbs + set). The default delay is 0, so other demos are unchanged.
- Known simulator limit: a GPI change that arrives while the reading core is inside a multi-cycle instruction is stamped at the end of that instruction. The SPI runs are unaffected, because PRU1's in-frame stalls are ≤ 3 cycles.
- SPI tests pin their clock and never read the repo `memory.cfg`. One user PC had an uncommitted 200 MHz `memory.cfg`; the committed file is 250 MHz.
- PRU1 does not use spec §5.2's "sample from the previous edge" technique (Ruling R20, an accepted deviation). It polls twice per bit and samples at the capture edge.
- Can-wait items are listed in the ledger under "minor (deferred)" and "parked".
