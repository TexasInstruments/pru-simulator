## Concern: R18 margins

The ruling's formula combined with the spec minimums (tLEAD = tLAG = 1 tCLK minimum, §3; tH/tL = ½ tCLK, 50 % duty) gives exactly −2.00 ns for tLEAD, tLAG and tH/tL at every rate, because the controller produces those times exactly at the design minimum (proven cycle-exact by test_every_half_period_is_exactly_k). As a result the "worst" row is now tH/tL −2.00 ns (the first of the tie) in every supported row of the JSON, the doc's supported tables, the "Fastest supported rate" limits text and the UI. It replaces tSU,MISO, which used to be the informative worst margin (for example 1.33 ns at 50 MHz). The UI test now expects tH/tL as the fixture's worst. I implemented the ruling literally and stated in docs/spi_link.md why the margin is −2 ns (pad skew could shorten these by that much on silicon). If that is not what the controller meant, two options:
- (a) Use a different design minimum for tH/tL, for example the 3-cycle minimum half period. This only moves the problem to k = 3.
- (b) Leave these design-constant rows out of the worst selection.

Either one is a one-line change in `measure_timing`, followed by `spi_sweep.py --write`.
