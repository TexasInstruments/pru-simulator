pif_eth Datapath

Ethernet frames leave PRU0 as an 8b/10b line-coded serial stream on channel 0 of the three-channel Peripheral Interface, cross a modelled wire, and are recovered by PRU1 — or tapped by the host and written out as a Wireshark trace.

PRU0 · pif_eth_tx.asm PRU1 · pif_eth_rx_o1_raw.asm channel 0, continuous mode 8b/10b · K28.5 125 Mbaud @ n=2

FIG 1The datapath, end to end

  • Continuous mode (tx_frame_size = 0) pops the TX FIFO one byte at a time as each finishes shifting out, so R31's occupancy field shows the true live queue depth. Run the FIFO dry and the frame ends.
  • K28.5 commas bracket every frame. They are idle fill between bursts and they give the receiver its symbol alignment — there is no preamble.
  • Start of frame is hardware. The line idles at 0 with sb_pol = 1, so capture auto-starts on the burst's first 1 bit. No firmware polling is involved.
  • End of frame is two zero bytes. One is not enough: 8b/10b permits a 5-bit run, which at 2× oversampling is 10 zero samples and can fill a whole capture byte on its own.

FIG 2One octet, one table read

The encoder does no arithmetic. Each octet indexes a 256-entry table in DRAM0 that holds both disparity variants of its 10-bit symbol plus the disparity that results — so encoding an octet is one LBCO, one branch on the running-disparity bit, and a shift into the packer.

RATEWhat the divider buys

The serialiser's bit clock is f_source / ((frac+1)(div_factor+1)). Everything downstream — the firmware's cycle budget per octet, the receiver's 2× oversampling, the FIFO slack — is set by that one divider, written as n below at a 250 MHz core clock.

The n=2 RX rung fits exactly: seven instructions plus a one-cycle DRAM write stall fill the eight-cycle budget with none of the FIFO's 32-cycle slack spare. That is a measurement of this simulator's modelled timing (write_latency = 1, jitter = 0), not a silicon claim.

FIG 3The host tap

PRU1 is one consumer of the line; the host is the other. The same serial transitions the receiver samples are read back by the Python layer, decoded against a golden reference, and written out as a pcap that dissects cleanly in Wireshark.

  • BERT frames carry 128 PRNG octets plus a 4-octet CRC-32 — no preamble, no header. They exist to be compared bit-for-bit against the reference stream.
  • UDP frames carry Ethernet/IPv4/UDP with "Hello World Text", padded to 60 octets plus FCS. Only the BERT path runs end-to-end through PRU1 — reconstruction needs the PRNG.
