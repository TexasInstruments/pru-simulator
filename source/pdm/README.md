# PDM microphone demo

Two PDM microphones are synthesised by PRU1 from 16 kHz audio clips and decoded by
PRU0 through the ICSS sigma-delta (SD) hardware into 16 kHz PCM. The simulator
runs both firmwares cycle by cycle; the dashboard's **Audio** view shows the
decoded PCM as two live spectrograms.

Design: `docs/superpowers/specs/2026-11-03-pdm-audio-demo-design.md`.
Verification report: `docs/reports/2026-11-03-pdm-audio-demo-report.md`.

## Signal chain

```
 clip L, clip R (16 kHz, 16 bit, shared RAM 0x12100)
        |
        v
 PRU1  pdm_gen.asm          2 x 2nd-order sigma-delta, 3.072 MHz clock
        |  R30.t0  clock                       one data line carries both mics:
        |  R30.t1  data  --- left bit  valid at the rising  clock edge
        |                    right bit valid at the falling clock edge
        v
 PRU0  SD hardware          ch0: SD0_CLK rising  edge, data SD0_D   (left)
        |                   ch1: SD0_CLK falling edge, data SD1_D   (right)
        |                   SINC3 decimation by 96 -> 32 kHz, ACC3 shadow
        v
 PRU0  pdm_rx.asm           comb, 63-tap FIR /2 -> 16 kHz, 20 Hz DC blocker, sat24
        |                   round-robin over the channels, once per SD window
        v
 shared RAM 0x10100 ...     PCM rings (signed 24 bit in int32), PCM_COUNT[k]
        |
        v
 PdmDemo (pdm_demo.py)  ->  ui/server.py pdm_* websocket  ->  ui/static/audio.js
                                                              (spectrograms, Booth)
```

Numbers: PRU clock 200 MHz on both cores. PDM clock 3.072 MHz = 65 + 5/48 PRU
cycles (43 short and 5 long periods per 48 = 3125 cycles, no drift, 5 ns jitter).
OSR 96 gives 32 kHz SINC3 output, the FIR decimates by 2 to 16 kHz PCM.
One spectrogram column is 8 ms of audio (256-point FFT, hop 128).

## Pins

| Signal | PRU1 (generator) | PRU0 (receiver) |
|---|---|---|
| PDM clock 3.072 MHz | R30 bit 0 (GPO0) | SD0_CLK (shared by ch0 and ch1) |
| PDM data, both mics | R30 bit 1 (GPO1) | SD0_D (ch0, rising edge) and SD1_D (ch1, falling edge) |

In the simulator the wire is `Simulator.attach_pdm_link("pru1", "pru0",
clock_pin=0, data_pins={0: 1, 1: 1})`. On hardware PRU1's GPO0 and GPO1 would be
wired to the SD0_CLK and SD0_D/SD1_D pads, or the real microphones replace PRU1.

## Shared-RAM map (ICSS shared RAM, `0x00010000`, 64 KB)

Offsets are relative to `0x10000` (`pdm_shared.inc`, `pdm_layout.py`).

| Offset | Size | Name | Writer | Meaning |
|---|---|---|---|---|
| `0x0000` | u32 | `HDR_MAGIC` | host | `0x50444D31` ("PDM1") |
| `0x0004` | u8 | `HDR_N_CH` | host | channels in the clip (2) |
| `0x0006` | u16 | `HDR_BLOCK` | host | PCM samples per block (128) |
| `0x0008` | u32 | `HDR_PCM_RATE` | host | 16000 |
| `0x000C` | u32 | `HDR_CLIP_LEN` | host | clip length in frames |
| `0x0010` | u32 | `HDR_GEN_POS` | PRU1 | frames fetched (k+1 while frame k plays; LEN at the end) |
| `0x0014` | u32 | `HDR_GEN_DONE` | PRU1 | 0/1, clip end reached |
| `0x0020` | u32[8] | `HDR_PCM_COUNT` | PRU0 | samples written per ring, stored after the sample |
| `0x0100` | 8 x 1 KB | PCM rings | PRU0 | ring k at `0x100 + k * 0x400`, 256 x int32; sample n at index `n mod 256` |
| `0x2100` | up to 32 KB | clip | host | interleaved L/R int16 frames, at most 8192 frames (0.512 s) |

`GEN_DONE` rises less than one PDM period before the last frame's last bits are
sampled (the generator fetches two half periods ahead), so the host adds 64
samples of flush before it calls the run finished.

PRU0 keeps all its filter state in its own DRAM0: FIR coefficients at `0x800`,
channel block k at `0x900 + k * 0x220` (eight blocks end at `0x1A00`).

## Cycle budgets

PRU1, `pdm_gen.asm` (per half PDM period; measured, see the header of the file):

| Half | Length | Busy | Padding |
|---|---:|---:|---:|
| low, with clip fetch | 33 | 28 | 5 |
| low, no fetch | 33 | 13 | 20 |
| low, clip end | 33 | 18 | 15 |
| high, short | 32 | 13 | 19 |
| high, long | 33 | 14 | 19 |

Padding is `LOOP`+`NOP` delay, which the simulator's idle skip collapses. The data
line changes 7 (left) / 6 (right) cycles after the opposite clock edge, so the
setup margin is **26 cycles (130 ns)** and the hold 6-7 cycles (30-35 ns).
In the fetch half, 4 cycles are spare: `LBBO` (3 cycles) plus `SBBO` (2 cycles)
may grow by 4 in total before the layout stops fitting.

PRU0, `pdm_rx.asm` (one SD window is 6250 cycles at 200 MHz; measured at N_CH = 2
over 600 windows by `tests/test_pdm_rx.py::test_worst_window_fits_budget`):

| Path | Cycles |
|---|---:|
| comb only (`w_comb`) | 48 |
| FIR + DC block + sat24 + publish on top (`w_fir`) | 905 |
| round overhead (wrap, event check, spin) | 8 |
| **worst window at N_CH = 2** | **1009** (16 % of 6250) |
| N_CH = 8 extrapolation: 8 `w_comb` + 4 `w_fir` + overhead | 4012 (64 %) |
| N_CH = 8 pessimistic (every FIR input negative, shadows one PDM period apart) | 4334 (69 %) |

The simulator models SD channels 0..2 only, so N_CH = 8 is a count of the
measured paths, not a run. It loads and assembles (see below).

### FIR stagger (note for mic-array work)

The FIR runs every second 32 kHz sample per channel. To spread the work, odd
channels drop one more warm-up sample than even channels, so even channels run
their FIR in one SD window and odd channels in the next, and a window runs at
most ceil(N_CH / 2) FIRs. Consequence: **the PCM of an odd channel is 1/32 kHz
(31.25 us) later than that of an even channel** for the same acoustic input. It is
invisible in a spectrogram, but a beamformer over a microphone array has to
compensate this known half-PCM-sample offset, or use same-phase decimation.
`reference.pcm_chain_for_channel(bits, ch)` is the one place that holds the rule.

## Simulator features the demo relies on

- **Pin-driven SD input** (`PdmLink`, `Simulator.attach_pdm_link`): PRU0's SD
  channels sample the pins PRU1 drives, with `CLK_SEL` and `CLK_INV` honoured, instead
  of the internal modulator. The default (internal modulator) is unchanged.
- **Exact idle skip** (`step_run`, `step_paced_many(..., idle_skip=True)`): NOP delay
  loops and R31 poll spins are advanced in one span. Bit- and cycle-identical to
  stepping; single-step, the MCP step tools and runs with the Signal Graph
  capturing never skip. It applies to every Run, not only this demo. The toolbar
  **Skip** button (Execute group) turns it off and on for the whole session. Off,
  Run steps every instruction: slower, same results. A config or clock change
  rebuilds the simulator and turns it back on.
- **Run-ahead scheduling** (`Simulator.run_ahead`): the producer (PRU1) runs a
  slice ahead and the consumer (PRU0) follows, instead of lockstep catch-up per
  instruction. It needs the four declared shared-RAM range lists and refuses
  (falls back to lockstep with a notice) if the two cores touch the same words,
  IEP, scratchpad/XFR, PERIF loopback or other cross-core windows.

## Speed

`env -u PYTHONPATH .venv/bin/python source/pdm/tools/bench.py --audio-ms 20`
(local machine, 200/200 MHz, wall time of the run only):

| mode | skip | wall s | audio ms | ms audio / s | s audio / min |
|---|---|---:|---:|---:|---:|
| lockstep | off | 36.28 | 20.00 | 0.551 | 0.0331 |
| lockstep | on | 34.68 | 20.00 | 0.577 | 0.0346 |
| run-ahead | off | 32.11 | 20.00 | 0.623 | 0.0374 |
| run-ahead | on (the demo) | 13.39 | 20.00 | 1.494 | 0.0896 |

A re-run with `--audio-ms 5` at the end of the project gave 1.514 ms audio/s
(0.0908 s/min) for run-ahead + skip. **The target of 0.1 s of audio per minute
is missed by about 10 %.** Compared with the starting point (0.61 ms/s with both
cores paced), run-ahead + skip is about 2.4x faster. The 450 ms speech clip
takes about five minutes of wall time.

Profile finding: under cProfile (which inflates the time; about 6 ms of audio
ran), `PeripheralInterface.advance_cycles` took 7.6 s of the 14.2 s that
`step_run` took in the run-ahead + skip case, about 54 %. Without the profiler 5
ms of audio takes about 3.3 s (1.514 ms/s). The PERIF model advances its three
channels on every PRU step even while the PERIF mux is disabled (both cores are
in GP/SD mode here). Skipping or batching that while PERIF is not enabled or its
channels are idle would roughly double the speed (about 0.18 s/min). This is a
core/PERIF change outside this project, deferred as **future work**.

## Booth steps (Demo D: PDM microphones to spectrogram)

Prerequisites: Python 3.10 or newer, and from the repository root
`pip install -r requirements.txt` (FastAPI, uvicorn, websockets).

1. From the repository root run `python3 ui/server.py` and open
   `http://127.0.0.1:8080/`. If port 8080 is busy, use `--port 8081` (and
   `--host 0.0.0.0` to serve other machines); the same can be set with the
   `PRU_SIM_UI_PORT` and `PRU_SIM_UI_HOST` environment variables.
2. Open the **Audio** tab.
3. Pick **Gen L** `speech_librivox.wav` and **Gen R** `chirp_lin_100_7000.wav`
   (or tick **Swap L<->R**). The first setup forces both PRU clocks to 200 MHz and
   shows a notice.
4. **Run**. The first spectrogram column needs 256 samples (16 ms of audio), so at
   about 1.5 ms of audio per second it appears after about 11 s; after that a new
   8 ms column follows about every 5 s. The progress bar and "ms audio / s" show how
   fast the simulation is. Left shows speech formants,
   right shows the chirp ridge climbing from 100 Hz to 7 kHz.
5. **Booth** shows only the pickers, Run/Stop and the two spectrograms at large
   size; **Exit booth** or Esc leaves it.
6. **Stop** pauses the run; **Run** continues from where it stopped. **Reset**
   (disabled while a run is going) restarts with the same clips from 0 and clears
   both pictures. Choosing other clips and pressing Run sets up again from 0.
7. Reloading or closing the tab that owns the run pauses it. After the page
   rebuilds both spectrograms from the server's history, **Run** continues
   without gaps. A second tab is a read-only observer: it shows "Running in another
   tab" and a snapshot refreshed every 5 s, and it cannot start or reset the run
   (Run and Reset are disabled; the server answers a second tab's setup/run/reset
   with an ownership error). Its **Stop** button is enabled and does stop the
   owner's run, because the server's `pdm_stop` is not owner-restricted.
8. Run loads `pdm_gen.asm` on PRU1 and `pdm_rx.asm` on PRU0 and zeroes their RAM
   (the notice says so). A Simulator-view Load, Load ELF, scenario, Reset or Hard
   reset, or a clock/config change, hands the simulator back: the PDM wiring is
   removed (link detached, every SD channel back on its internal modulator, SD
   filter state and GPCFG mux as before the first setup), and the next Audio Run
   sets the demo up again from 0.

How long it takes: the simulator does about 1.5 ms of audio per wall second. A run
ends when the longer clip and a 4 ms flush have played, so the 450 ms speech clip
takes about 5 minutes (450 / 1.5 = 300 s), and two 250 ms clips (the chirps and
tones) about 3 minutes (167 s). With speech on one side and a 250 ms chirp on the
other, the chirp side stays blank after 250 ms (about 2 min 50 s) while the speech
side keeps going. These are timings of the development PC; a slower machine takes longer.

`ui/server.py` rewrites `memory.cfg` (clock forcing). Local, dirty-by-design
file: never commit it. To exercise the page or the websocket API without touching
it, use `source/pdm/tools/ui_check.py` (below).

Checked in a real browser (headless Chromium) with `ui_check.py browser`: tab 1
with Run, Booth, reload and Run again, and the observer tab 2. Not checked in a
real browser: real fullscreen (needs a user gesture), the dark and contrast
themes, and a run to the end of a clip.

is open, because that file is only on branch `docs/electronica2026-howto`.

## Hardware porting notes

This project is simulator only; nothing here was run on silicon.

- **GPCFG SD mux**: PRU0 GPI mux must be in SD mode (ICSSG GPCFG0
  `PRU0_GP_MUX_SEL = 3`); otherwise `R31[28]` never rises and `PDM_WAIT` spins
  forever. `SD_CFG_REG`: `SHARE_EN = 0`, `MAN_SD_EN = 0`. In the simulator
  `PdmDemo.setup` does the GPCFG write.
- **Pinmux** for the SDn_D / SDn_CLK pads in use, and PRU1 GPO0/GPO1 if PRU1 is
  the stimulus.
- **INTC**: map system event `16 + BLOCK_EVENT` to a host interrupt.
- **CTBIR**: `C24_BLK_INDEX = 0` so `c24` is PRU0's DRAM0 at local address 0
  (the filter state and the FIR coefficients live there).
- **IM73D122 edge check**: the demo has the left mic on the rising and the right
  mic on the falling clock edge. Check this assignment (and the select-pin to
  edge mapping) against the IM73D122 datasheet before using real microphones.
- **SD `ch_sel` latency**: `pdm_rx.asm` switches the R31 channel view with one
  `mov r30.b3` and spins on `R31[28]`. The simulator switches at once; on silicon
  there may be one cycle before R31 shows the new channel. If a stale `valid` is
  seen in the first spin cycle, add one `nop` after the `mov` (8 cycles per window).
- **Shared-RAM `LBBO` arbitration**: the simulator gives PRU1's clip fetch a fixed
  3 cycles (`LBBO`) and 2 cycles (`SBBO`). On silicon the latency depends on
  arbitration with PRU0's ring writes, which puts jitter on the clock in fetch
  periods; the 4 spare cycles cannot absorb a variable stall. Measure the worst
  case, re-balance `CFG_LBBO_CYC`/`CFG_SBBO_CYC`, or move the clip to PRU1's DRAM.
- **8-microphone array** (`N_CH` up to 8): the code assumes pair p = channels 2p
  and 2p+1 share a data line; even channels sample their own `SDk_CLK` rising edge,
  odd channels the group clock inverted, so the PDM clock goes to
  SD0/2/3/4/6_CLK. See the header of `pdm_rx.asm`. Also see the FIR stagger above.

## Assembling with clpru

Both firmwares assemble with TI clpru 2.3.3 (`-v4` is ICSSG):

```
~/ti/ti-cgt-pru_2.3.3/bin/clpru -v4 -c -I source/pdm \
    -I ~/ti/ti-cgt-pru_2.3.3/include --output_file=<scratch>/pdm_gen.obj source/pdm/pdm_gen.asm
```

`pdm_rx.asm` with `N_CH 8` assembles as well, and `N_CH 9` stops at the `.emsg`
guard. Write the object files outside the repository.

### Checking the Audio view

`ui/server.py` forces both PRU clocks to 200 MHz by rewriting `memory.cfg` in the
project root, so the check tool never starts the repository's own server. It
copies the working tree to a temporary directory, starts the server there on a
free port, runs the check, stops the server and reports whether the repository's
`memory.cfg` is unchanged (exit code 1 if it is not).

```
python3 source/pdm/tools/ui_check.py ws                        # websocket flow, about 15 s
python3 source/pdm/tools/ui_check.py browser --shots out/      # needs Chromium or Chrome, about 2 min
```

`ws` sets up speech + chirp, runs chunks, disconnects, reconnects and compares
`pdm_history` with the streamed samples, continues the run and resets. `browser`
drives the page over the DevTools protocol: Audio tab, clips, Run, Booth in and
out, a second tab as observer (and its Stop), reload and Run again, with
screenshots. `--chrome` selects the browser binary.
